# 合同台账统计（Contract Ledger Stats）

> v2.0.0 专家级（2026-09-07）：补齐九要素——定位声明、触发条件、步骤化工作流（含检查点）、输出规范、边界与反模式、依赖降级、实战范例；两种台账结构（宽表/长表）识别逻辑与字段映射表原文保留。

## 定位声明

本技能是合同台账的付款/开票统计引擎：读取合同台账 Excel，自动识别字段与台账结构，输出含总览、明细、付款分析、开票核销、预警清单五个 sheet 的规范报表。给工程/分包/采购管理场景的合同执行情况盘点用。依赖 `scripts/contract_ledger.py`（inspect/stats 双命令，openpyxl 实现）。

## 触发条件

**场景清单**（与 description 呼应）：

- 上传合同台账 Excel，要求统计付款情况、开票情况、欠付清单
- "统计一下合同付款情况"、"哪些合同付款率低于 X%"、"已付未开票的有哪些"
- 月度/季度合同执行情况汇总
- 台账结构未知，需要先识别字段再统计

**中文触发词**：合同台账、付款统计、开票统计、付款进度、欠付清单、开票核销、合同执行汇总。
**English triggers**：contract ledger statistics、payment summary、invoice reconciliation。

**不适用**：合同起草、合同审查、法律风险分析（用合同审查类技能）；非台账类纯财务记账。

## 你的工作方式

用户提供合同台账 Excel（或指明台账所在知识库位置），你负责：
1. 先跑 `inspect` 确认字段识别正确（识别错误时给出台账列名调整建议）；
2. 再跑 `stats` 生成统计报表 Excel（5 个 sheet）；
3. 向用户汇报关键统计结论（合同份数/总金额/已付款/未付款/开票/预警），并说明报表结构。

**为什么先 inspect**：不同项目的台账列名千差万别（如"收/支付金额"vs"已付款金额"），先确认字段映射能避免统计口径错误。inspect 输出字段识别表，发现未识别列时提示用户调整列名或人工核对。

## Phase 0｜统计前校验（未过不进主流程）

| 检查项 | 通过标准 | 未过动作 |
|---|---|---|
| 台账结构 | 已识别为宽表（合同执行台账）或长表（付款明细） | 先识别结构 |
| 字段完整 | 合同名称、金额、付款、开票等关键字段齐备 | 列出缺字段 |
| 金额口径 | 含税/不含税、币种与单位明确 | 明确口径 |
| 时间范围 | 统计期间与截止日明确 | 明确期间 |
| 旧格式 | .xls 等旧格式已转换为 .xlsx | 先转换再统计 |

🔴 检查点：任一检查项未过，先补齐再进入分步工作流。

## 分步工作流

**输入**：合同台账 Excel（.xlsx；.xls 先转）→ **处理**：inspect 核字段 → stats 出报表 → **输出**：5-sheet 统计报表 + 口头汇报 → **检查点**：字段识别表、金额单位、预警口径。

1. **确认输入**：文件存在且为 .xlsx；.xls 老格式先转换：
   ```bash
   soffice --headless --convert-to xlsx --outdir /tmp 台账.xls
   ```
2. **字段体检（必做第一步）**：
   ```bash
   python3 scripts/contract_ledger.py inspect --file 台账.xlsx
   ```
   **检查点 A**：合同名称、合同金额、已付款等关键列全部识别；未识别的关键列请用户改名（对照字段映射表）后重跑。
3. **生成报表**：
   ```bash
   python3 scripts/contract_ledger.py stats --file 台账.xlsx --out 合同台账统计报表.xlsx
   ```
   可选参数：
   ```bash
   #   --ratio-threshold 0.8    付款率预警阈值（默认 80%，低于即预警）
   #   --unit 万元              金额单位（默认自动识别表头中的"单位：万元/元"）
   #   --use-ledger-unpaid      未付款用台账"应付未付"列原值（业务口径，可为负=超付待扣回）；
   #                            默认用"金额-已付款"统一测算口径
   ```
4. **检查点 B**：打开报表核对——00 总览的合同份数与明细行数一致；金额单位为万元；预警清单条数与总览预警事项数一致。
5. **汇报**：合同 X 份、总金额 X 万元、已付 X 万元（比例 X%）、未付 X 万元、开票 X 万元、预警 N 项；重点提示欠付金额大的合同和已付未开票合同。具体数字以实际统计为准（【待核：以 stats 输出为准】）。

## 输出报表结构（stats 生成）

| Sheet | 内容 |
|-------|------|
| 00_统计总览 | 合同份数、合同总金额、累计已付款、尚欠未付款、累计开票、综合付款比例、综合开票比例、预警事项数 |
| 01_合同明细 | 每份合同的金额/已付款/付款比例/未付款/累计开票/开票-付款差额/执行状态，末尾合计行 |
| 02_付款分析 | 按执行状态汇总、乙方合同金额 TOP10、付款月度趋势（长表） |
| 03_开票核销 | 每合同开票比例、已付未开差额（欠票）、核销状态（已核销/已付未开/已开未付/未开票） |
| 04_预警清单 | 欠付合同、付款率低于阈值、已付未开票、已付款但无开票记录 |

**报表格式规范**：标题方正小标宋 16 号居中、表头灰底 CC/CC/CC 加粗、金额两位小数、单元格居中、合计行加粗。

## 统计口径（重要）

- **金额统一按"万元"**：表头标"单位：元"的自动 ÷10000 转换，报表统一标万元；
- **未付款 = 合同金额 − 已付款**（默认统一测算口径，不采用台账自填列，避免口径不一致）；
- **台账业务口径**：台账含"按合同约定应付未付"列（含负数=超付待扣回、未计价等复杂情形）时，加 `--use-ledger-unpaid` 用台账原值，只计正数欠付——如临潼自有分包商产值付款统计表（材料合同未计价、和解协议冲抵等）；
- **付款比例 = 已付款 ÷ 合同金额**；
- **合计/小计/总计行自动跳过**，不作为合同数据；
- 长表台账无开票列时，开票统计为 0 且预警"已付款但无开票记录"——此时应提示用户补充开票台账后合并统计。

## 边界与反模式

**不适用场景**：合同起草/审查/法律风险分析；非台账类记账。

**禁止行为**：

- 禁止跳过 inspect 直接 stats——列名映射错误会让全部统计失真。
- 禁止混用两种未付款口径——一个报表内要么统一测算口径、要么统一台账业务口径。
- 禁止改动 scripts/contract_ledger.py 的字段关键词表——新列名优先建议用户改台账列名。
- 禁止把合计行当合同数据统计——脚本已自动跳过，人工复核时同样剔除。

**常见问题处理**：

- **inspect 显示某列"未识别"**：该列未参与统计。如果该列是关键数据（如金额列名特殊），建议调整台账列名为标准关键词（见字段映射表）后重跑；
- **.xls 文件打不开**：openpyxl 只支持 .xlsx，先用 soffice 转换（见实战范例 2）；
- **两级表头（大类+子项）**：脚本自动取子表头行，上一行仅用于补全空列名；
- **合计行混入数据**：脚本按"合同名称列/付款依据列含合计/小计/总计"自动跳过；
- **金额单位混乱**：脚本按表头"单位：X"自动识别，识别失败时用 `--unit 万元` 强制指定。

## 实战范例

### 示例 1：宽表（合同执行台账）付款开票统计

用户上传「利川项目合同执行台账.xlsx」说"统计一下合同付款情况"：

```bash
python3 scripts/contract_ledger.py inspect --file 利川项目合同执行台账.xlsx
python3 scripts/contract_ledger.py stats --file 利川项目合同执行台账.xlsx --out 利川项目合同台账统计报表.xlsx
```

汇报要点：合同 X 份、总金额 X 万元、已付 X 万元（比例 X%）、未付 X 万元、开票 X 万元、预警 N 项（重点提示欠付金额大的合同和已付未开票合同）——数字以实际统计为准【待核：以报表 00_统计总览 为准】。

### 示例 2：长表（付款明细表）付款进度

用户上传「竣工验收相关合同已付款明细表.xls」说"统计这些合同的付款进度"：

```bash
# .xls 老格式先转 .xlsx（沙箱内 soffice 转换）
soffice --headless --convert-to xlsx --outdir /tmp 竣工验收相关合同已付款明细表.xls
python3 scripts/contract_ledger.py inspect --file /tmp/竣工验收相关合同已付款明细表.xlsx
python3 scripts/contract_ledger.py stats --file /tmp/竣工验收相关合同已付款明细表.xlsx --out 付款进度统计.xlsx
```

长表无开票列 → 报表预警"已付款但无开票记录"，向用户说明需补充开票台账。

### 示例 3：预警阈值调整

用户说"把付款率低于 60% 的合同单独列出来"：

```bash
python3 scripts/contract_ledger.py stats --file 台账.xlsx --out 报表.xlsx --ratio-threshold 0.6
```

### 示例 4：台账业务口径（应付未付列）

用户说明台账里有"按合同约定应付未付"列（含超付负数、材料合同未计价）：

```bash
python3 scripts/contract_ledger.py stats --file 台账.xlsx --out 报表.xlsx --use-ledger-unpaid
```

## 输出质量规范

- **数据溯源与分级**：每项统计结果标注来源文件与字段——P0 台账原件与原始付款凭证｜P1 财务系统导出｜P2 人工汇总；无来源者标【待核：需补来源】。
- **缺口显性化**：缺字段、缺期间、金额为空一律写【待核：具体项】，不以 0 代替。
- **事实与判断分离**：付款额、开票额、余额属事实段直陈；付款风险与预警判断以「判断：」起头并附阈值依据。
- **能力边界提示**：本输出为台账统计结果，不替代财务账与审计结论；对外使用须经财务部门确认。

## 反幻觉约束

不得编造合同金额、付款记录与开票数据；所有数字须来自台账文件，识别失败即标注失败原因，不以估算填补。

## 交付附加与迭代

交付时按需追加：关联提示、要点归纳（3—5 条，如付款进度、未开票金额、预警清单）、下一步动作（可执行项）。

多轮迭代：交付后说明可调整维度（期间／台账类型／预警阈值），指定后直接改。

## 交付自检表

| 检查项 | 标准 | 不达标动作 |
|---|---|---|
| 结构识别 | 宽表/长表判定正确 | 重新识别 |
| 字段映射 | 字段与口径一致 | 修正映射 |
| 金额勾稽 | 明细与汇总相符 | 复核重算 |
| 来源可溯 | 结果可回溯至台账 | 回补来源 |
| 阈值一致 | 预警阈值与约定一致 | 调整阈值 |

| 交付物 | 命名规范 | 格式 | 内容要件 | 交付前门禁 |
|---|---|---|---|---|
| 统计报表 | `{台账名}-合同台账统计报表-{YYYYMMDD}.xlsx` | xlsx（5 sheet） | 00 总览 / 01 明细 / 02 付款分析 / 03 开票核销 / 04 预警清单；金额万元两位小数 | `python3 scripts/ledger_check.py --file 报表.xlsx` |
| 台账字段体检单 | 控制台输出（可留存） | 文本 | 字段映射命中表、未识别列清单、结构判定（宽表/长表） | `scripts/contract_ledger.py inspect` |
| 口径说明 | `{台账名}-口径说明-{YYYYMMDD}.md` | Markdown | 未付款口径（测算/台账业务）、金额单位、预警阈值、统计期间 | 人工复核 |
| 口头 / 汇报要点 | — | 文本 | 合同份数、总金额、已付款及比例、未付款、开票、预警 N 项及其重点合同 | 与 00 总览逐项对齐 |

交付三条命门：先 inspect 后 stats；两种未付款口径不混用；数字全部可回溯至台账（无来源不报数）。

## 降级路径与失败模式

> 统计链路的**容错**底座：把口径错位、字段失配、勾稽不平这些**失败模式**前置为可执行的降级动作，**防御**「报表漂亮但数字错」的后果。

| 场景 | 触发条件 | 降级处置 |
|---|---|---|
| .xls 旧格式打不开 | openpyxl 报 bad zip / 不支持 | **回退到** soffice 转换（`soffice --headless --convert-to xlsx`）；转换**异常**时请用户另存为 .xlsx |
| 关键列未识别 | inspect 输出未命中合同金额/已付款等 | **补救**：对照字段映射表建议用户改名后重跑；不得改脚本关键词表，也不得凭猜测映射 |
| 金额单位不明 | 表头无「单位：元/万元」 | 用 `--unit 万元` 强制指定并在口径说明标注；单位口径不一致时不出表（**边界条件**） |
| 长表缺开票列 | 付款明细表无开票字段 | 开票统计记 0 并预警「已付款但无开票记录」；**兜底**提示用户补开票台账后合并统计，不以 0 掩盖缺列 |
| 合计行混入主体数据 | 合同名称列出现合计/小计/总计 | 触发行级**错误处理**：脚本自动跳过；若仍混入则**断点续跑**重跑该台账并复核 00 与 01 行数 |
| 两种口径结果冲突 | 测算口径与台账业务口径差异大 | 单报表内只保留一种口径；差异在汇报中显性说明，**重试**前先确认口径来源 |
| 无台账文件 | 用户口述金额要求汇总 | 拒绝编造；请用户提供台账或指明知识库位置（**失败分支**：不产出任何数字） |
| 报表写出失败 | 目标文件被占用或磁盘异常 | **重试**换输出路径；仍失败则输出 CSV 明细 + Markdown 兜底报表并标注 |

**失败模式记录格式**（每次统计新建，一行一条）：

```csv
日期,台账,失败模式,触发条件,降级处置
2026-10-04,某项目执行台账,关键列未识别,「付款总额」列未命中,建议改名为「累计支付总额」后重跑 inspect
2026-10-04,某付款明细表,长表缺开票列,无开票字段,开票记 0 并预警已付未开票，提示补开票台账
```

### 退出码与重试超时补充

在上一节失败场景之外，补运行期约定：退出码 0 正常／1 输入不合规（须指出缺哪一项，不返回 None）／2 依赖缺失或运行失败／3 无命中／4 路径或权限不可写。单脚本超时 120 秒，超时或网络类失败重试 1 次（间隔 3 秒），仍失败进入上一节对应降级分支；批量任务分批处理，失败批次落盘支持断点续跑。必填参数 `--headless`, `--convert-to`, `--outdir` 在入口即校验。

## 常见问题（FAQ）

**问：直接跑 `contract_ledger.py` 报「找不到命令 / 模块」怎么办？**
答：多为依赖未装或未在技能目录下执行。先 `cd` 到技能根目录，按退出码 2 的提示安装依赖，再重跑；仍失败改走手工流程，不用脚本硬凑结果。

**问：`--headless` 传了但结果为空？**
答：先确认输入确实含该类内容，再按无命中的处置口径处理——换用更宽的关键词或改用编号/名称直查。空结果不代表没有，但绝不能凭印象补全。

**问：`--convert-to` 和默认行为有什么区别？**
答：默认口径面向常见情形，显式传参用于边界情形；两者结果不同时，以显式传参为准，并在交付说明里写明用了哪个口径。

**问：结果与手上的资料对不上怎么办？**
答：以原始依据为准，脚本结果只作检索与整理的辅助。对不上时先核对口径（年份、版本、计量单位），再判断是谁的问题，不直接采信任一方。

**问：能不能一次处理一大批？**
答：可以，按批处理并保留失败清单。批内单条失败不影响其余，失败项集中处理后补跑，不要整批重来。

**问：`--help` 里没有我要的参数？**
答：说明该情形不在脚本覆盖范围。走技能正文的门禁与降级口径手工处置，或按 `references/` 里的方法自行处理，不要臆造参数。

**问：输出的结论能直接对外用吗？**
答：不能直接对外。脚本产出为工作底稿，对外前须按本技能的红线与交付规范复核，涉及责任认定的须经责任人签认。

**问：换台机器跑，结果会不一样吗？**
答：按本技能的输出约定，同输入应同输出。若有差异，先查依赖版本与数据文件版本，两者一致仍不同则是缺陷，需记录并反馈。

**问：数据多久更新一次，会不会过时？**
答：本技能以脚本收录与 `references/` 内容为准，时效性由使用者核对。引用前确认版本年份，涉强制性或时效敏感内容必须回溯原始出处。

**问：跑完之后还要做什么？**
答：按门禁逐条自检，确认无【待核】占位、字段齐全、结论有依据；再按交付规范输出，并留存本次运行记录以便复核。

## 红线声明

本技能仅限合同台账付款/开票统计用途。以下为固定拒绝口径：

1. 不得凭记忆或估算编造合同金额、付款记录与开票数据，无台账不出数；
2. 不得跳过 inspect 直接统计（列名映射错误会使全部统计失真）；
3. 不得在单张报表内混用两种未付款口径；
4. 不得改动 `scripts/contract_ledger.py` 的字段关键词表来「凑」识别结果；
5. 本输出为台账统计结果，不得用于替代财务账、审计结论或结算审核（分别转财务与结算审核路径）；
6. 不得将含商业敏感金额的台账原文上传至公共平台或无关第三方。

## 买家准备（调用前必读）

本技能在调用过程中会触发支付宝按次扣费，**买家侧需要具备 AI 支付能力**，否则无法完成付款。

| 买家类型 | 是否可直接支付 | 处理方式 |
|---|---|---|
| 已开通「支付宝 AI 付」的智能体 | ✅ 可以 | 直接调用，按提示扫码/确认付款 |
| 通用大模型 App（如千问等） | ❌ 不能 | 提示用户更换客户端或安装下列组件 |
| 自建 Agent 环境 | 需安装 | 执行下面的安装命令 |

自建 Agent 安装买家支付能力：

```bash
npx -y @alipay/agent-payment@latest install
```

安装后 Agent 获得 `alipay-bot` 命令，可完成「请求 → 402 → 生成支付 → 扫码付款 → 携凭证重试 → 验付 → 履约」。

注意事项：

- 付款账号需已实名；同一笔交易的买家与卖家不能为同一实名主体。
- 支付在弹出的支付宝收银台完成，完成后 Agent 自动重试原请求，无需用户再次操作。
- 未完成付款前，服务端不会产出任何实质性成果。
