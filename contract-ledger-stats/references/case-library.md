# 案例库（合同台账统计）

> 本文件为 contract-ledger-stats 的脱敏范式案例集，供台账结构识别、口径选择与预警处置参照。
> **来源**：正邦水务/建工实务台账范式（脱敏）与财务、工程计价公开依据；每案口径均可**溯源**至原始台账字段，
> 数字一律以实际 stats 输出为准【待核：以报表 00_统计总览 为准】。

## 案例一：宽表（合同执行台账）——利川项目工程建设其他费

- **情形**：一行一合同的执行台账，含合同金额、累计支付总额、已付款比例、累计开票金额、执行状态列。
- **处置**：`inspect` 确认字段映射（"累计支付总额"→已付款、"执行情况"→执行状态）后 `stats` 出五表报表。
- **口径**：未付款 = 合同金额 − 已付款（统一测算口径）；合计/小计行按关键词自动跳过。
- **要点**：识别率低于 60% 时**回退**人工 schema 映射，只对已映射列出表并标注未覆盖列。

## 案例二：长表（付款明细表）——竣工验收相关合同已付款明细

- **情形**：一行一次付款，含"收/支付日期""收/支付金额""付款依据"列，按合同名称聚合。
- **处置**：.xls 先经 soffice 转 .xlsx，再 inspect → stats。
- **口径**：长表无开票列时开票统计记 0，并预警"已付款但无开票记录"；须提示用户补开票台账后合并统计，
  不得以 0 **兜底**掩盖缺列。

## 案例三：台账业务口径——临潼自有分包商产值付款统计

- **情形**：台账含"按合同约定应付未付"列，存在超付负数、材料合同未计价、和解协议冲抵等复杂情形。
- **处置**：加 `--use-ledger-unpaid` 采用台账原值，只计正数欠付。
- **口径**：同一报表内禁止混用两种未付款口径；两种口径结果差异须在汇报中显性说明。
- **要点**：负数（超付待扣回）在报表中保留原值并加备注，不静默取绝对值。

## 案例四：预警阈值调整——付款率低于 60% 的合同

- **情形**：管理层关注付款进度异常合同。
- **处置**：`--ratio-threshold 0.6` 重跑；04_预警清单同步按新阈值重算。
- **口径**：阈值由用户指定并写入交付说明；阈值口径不一致时不得出表（**边界条件**）。

## 案例五：两级表头与单位混乱

- **情形**：台账第一行是大类（"付款情况"），第二行才是子项（"已付款金额"）；表头标"单位：元"。
- **处置**：脚本自动取子表头行，上一行仅用于补全空列名；金额自动 ÷10000 统一为万元。
- **要点**：单位识别失败时用 `--unit 万元` 强制指定，并在汇报中注明单位口径。

## 案例六：来源不可溯的统计请求

- **情形**：用户口述若干金额要求"帮我汇总一下"，未提供台账文件。
- **口径**：拒绝凭记忆编造统计数（见 SKILL.md 红线声明）；请用户提供台账文件或指明知识库位置后再统计。
