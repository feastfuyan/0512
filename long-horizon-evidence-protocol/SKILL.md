# 长程任务证据链协议（Long-Horizon Evidence Protocol）

来源：PA-Team-Trial-20261015-ContextReturn 包（pa-cr1-20261015）结构提炼。适用于跨多轮、多阶段、可交付物的长程任务。

## 一、分轮运行，轮轮留痕（ContextReturn 核心）
- 长任务按轮次编号执行：r0, r1, r2… 每轮一个目录或一组同名文件。
- 每轮固定三件套：`rN-<主题>.json`（结构化结果）+ `.stdout.log` + `.stderr.log`。
- **失败轮不删除、不覆盖**（如 r0-windows-handle-failure 保留）。失败本身就是证据，修复轮（r1-handle-fixed）与失败轮对照可审计。
- 目录命名：`evidence/<任务名>-r1/`。

## 二、阶段性验收快照
- 每阶段结束写 acceptance-summary：schema、时间、source_sha、测试数、`all_exit_zero`、明确 scope（验证了什么、没验证什么）。
- 声明只说「已验证的范围」，未验证项显式列入「已考虑而未作成功判断」清单。

## 三、独立复核门控
- 设计 → 实现 → 复核三段分离：先出方案（含 SHA/基线），自检通过后仍标注「等待独立复核，不以自检替代」。
- 多轮审查闭环：审出 Important 问题 → 修复 → 复核关闭，逐条表格记录（问题｜最小修订｜状态）。
- 禁止把设计层结论替代代码/实际验收。

## 四、来源与包装（交付物场景）
- 交付前记录 provenance：来源路径、字节数、SHA256、验收结果。
- 固定发布配置：只允许指定基线/分支，改动已审内容即拒绝。
- 交付回执与归档哈希分离，避免自指。

## 五、落地到本人工作流（OpenClaw 适配）
1. **多阶段任务开始时**：在工作区建 `evidence/<任务名>-<日期>/` 目录，规划轮次编号。
2. **每轮结束**：落 `rN-*.json` + 日志三件套（exec 输出重定向保存）。
3. **失败即记录**：失败轮文件保留，下一轮修复对照。
4. **汇报口径**：只声明已验证范围；未验证项明确列出；不用「应该没问题」代替验证。
5. **重大交付**（报告/代码包/正式文件）：附 provenance（来源、SHA、生成方式），先独立复核（subagent 或换模型交叉验证）再交付。
6. **与现有规则衔接**：multi-round 代码审查闭环、报告三件套、clawphylax_reconcile 交付前对账，均视为本协议的既有子集。

## 触发条件
- 任务预计 >3 轮工具交互且有交付物；
- 用户要求「验证」「审计」「可复现」；
- 多 agent 管线或跨天延续任务。
