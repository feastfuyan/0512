# 合同要素台账

把散落在各人电脑里、签完就没人管的合同，一次变成可筛选、可核对、可提醒的结构化台账。回答三个具体问题：**这批合同一共多少钱**、**什么时候到期**、**付款节点加起来对不对得上**。

纯本地运行，**合同数据不出机**。合同含商业条款、金额与当事人信息，属于敏感商业信息——本工具不做任何联网查询，不上传、不采集、不留存，也不调用任何模型。

---

## 30 秒跑通

```bash
python -m pip install "pandas>=2.0" "openpyxl>=3.1" "pypdf>=5.0" "python-docx>=1.1"

# 0) 没有合同也能先跑一遍：现场生成四份风格不同的样本
python examples/make_samples.py ./samples

# 1) 先自检依赖，并摸清目录里有哪些文件、有没有扫描件
python scripts/contract_toolkit.py info ./samples --probe-text

# 2) 处理真实合同之前，先核对字段有没有认对（重要；强烈建议带 --our-name）
python scripts/contract_toolkit.py parse ./samples/01_采购合同_星辰科技.txt --probe --our-name "北京星辰科技有限公司"

# 3) 批量生成台账（合同台账 + 付款节点 + 抽取候选 + 解析告警，四 sheet）
python scripts/contract_toolkit.py parse ./合同 ./合同台账.xlsx --our-name "北京星辰科技有限公司" -v

# 4) 台账体检 / 到期清单 / 跨合同汇总
python scripts/contract_toolkit.py check  合同台账.xlsx 合同体检.xlsx --as-of 2026-10-04
python scripts/contract_toolkit.py expire 合同台账.xlsx 合同到期.xlsx --within 90
python scripts/contract_toolkit.py compare 合同台账.xlsx 合同汇总.xlsx --group-by 对方名称 --fields 违约金比例,税率

# 5) 没有 Excel 的接收方：输出路径写 .html 就是一份单文件自包含报告
python scripts/contract_toolkit.py check 合同台账.xlsx 合同体检.html --as-of 2026-10-04

# 6) 付款核销（交给 reconcile-toolkit，本工具只产出数据）
python examples/make_payment_samples.py ./samples/示例银行流水.csv
```

## 为什么值得用

| | |
|---|---|
| **金额抽取不做黑箱** | 先捞全部候选，再按锚点打分消歧（总价类锚点优先，单价/税率/节点款/违约金分别降权）。**落选候选全部保留**在「抽取候选」sheet，每一条都能追溯到原文片段和打分理由 |
| **大小写交叉验证** | 「陆拾万元整（600,000.00元）」两个来源互相验证，一致则双向加分，不一致则标出来 |
| **抽不到就明说** | 低置信度字段直接写进「待确认字段」列，不假装抽准了。**空值不参与任何计算**——不是拿 0 去比 |
| **确定性体检** | 8 条规则全是算术与逻辑判断，不靠模型：节点金额合计 vs 合同金额、比例合计、日期逻辑链、大写一致、税率区间… |
| **到期分档** | 已到期 / 即将到期 / 正常（未到期）/ 无到期日期。**没有到期日的单独一类**，不混进「未到期」冒充有效 |
| **输入有交代** | 扫描件、旧版 `.doc`、`照片.jpg`、`附件清单.xlsx` 等都会明确列出并各占一行台账（状态为「异常/未提取」），不会静默跳过——**输入里有什么、台账里有几行，对得上**（v1.0.1 起对所有格式成立，此前只对 `.doc` 成立） |
| **子目录不漏收** | 合同按年份、按对手方分目录存放是常态。**v1.0.2 起子目录默认一并处理**（旧版要显式加 `--recursive`，而 help 文字写的是「默认开启」——照着 help 理解，子目录里的合同就被静默漏掉了） |
| **阈值可以按批次调** | `--conf-threshold` 调「待确认字段」的门槛（默认 0.70）。写得规范的批次调高、逼自己多看一眼；写得散的批次调低、免得整列都是「待确认」而失去信号 |
| **报告能直接发给不装 Excel 的人** | 输出路径写 `.html` 即得单文件自包含报告：内联样式、零外部资源、断网可看；超长表只预览前 300 行并注明 |
| **扣留项不误算** | 质保金/保证金标为「扣留项」，不参与「比例合计 = 100%」——它是从尾款里扣的，不是独立支付节点 |
| **数据不出机** | 无任何网络请求，不调用任何模型 |
| **原始合同只读** | 不生成、不修改、不移动、不删除任何合同文件，所有写入都落在你指定的输出路径 |

## 子命令

| 子命令 | 作用 |
|---|---|
| `info` | 依赖自检 + 目录摸底（含本次处理范围）；`--probe-text` 实际读一遍，识别无文本层的扫描件 |
| `parse` | 合同 → 台账（PDF/DOCX/TXT/MD 自适应）。`--probe` 单份核对字段与候选；`--our-name` 指定我方全称（也可用环境变量 `CONTRACT_OUR_NAME` 或 `.contract-toolkit.yaml` 配一次）；`--conf-threshold` 调待确认门槛；`--no-recursive` 只看当前层；`--dry-run` 只统计 |
| `check` | 台账体检 8 条规则：节点合计 / 比例合计 / 日期逻辑 / 金额为正 / 大写一致 / 税率区间 / 关键字段 / 到期状态 |
| `expire` | 到期清单，按期分档；`--within` 定义「即将到期」的提前天数 |
| `compare` | 按分组列汇总合同数/金额/到期区间，并按指定要素列统计取值分布（暴露同批合同条款不一致） |

输出格式按接收方选：`.xlsx`（推荐，多 sheet 一个文件）／`.csv` ／ `.tsv`（退化为同名多文件，给要接着做数据处理的人）／`.html`（单文件自包含报告，给不装 Excel 的人）。`parse` / `check` / `expire` / `compare` 都支持这三种。

### 一个必须注意的坑：空的字段不是 0

台账里「合同金额」为空，意思是**没抽到**（或合同本身没约定），**不是 0 元**。同理「到期日期」为空不等于「永久有效」。

所以：

- 体检时**空值不进分母** —— 所以你会看到「比例合计 1/2 通过」，那个 1 是「只有 1 条有数据可校验」。它由「关键字段」规则单独抓，不是漏检
- `expire` 把「无到期日期」单列一类并给出条数
- 台账里可能出现**状态为「异常/未提取」的行**（扫描件、`.doc`、`.jpg` / `.xlsx` 等不支持的格式），这是刻意的：宁可多一行说明「这份没处理」，也不要让你以为输入里本来就没有它。需要干净数据时按「处理状态」列筛掉
- `info` 的「合计」= `parse` 的「处理 N 个文件」= 台账行数（隐藏文件与 `.git` / `node_modules` / `__pycache__` 不计入）。三者不等就是缺陷

### 另一个坑：甲乙方角色要你告诉我

合同里写「甲方」「乙方」是相对称谓。不告诉我方全称，脚本只能按「先出现的角色」猜，并会在「解析告警」里明说。

**批量处理时始终带 `--our-name "我方公司全称"`** —— 这一条能把「我方角色 / 对方名称」两列从「猜」变成「定」。

每批都手敲太麻烦，可以配一次（优先级：命令行 > 环境变量 > 配置文件）：

```bash
export CONTRACT_OUR_NAME="北京星辰科技有限公司"
```

或在本机放一个 `.contract-toolkit.yaml`（会从输入目录及其上级、当前目录、用户主目录依次查找）：

```yaml
# 我方主体，用于区分甲乙方
our_name: 北京星辰科技有限公司
```

命中默认值时输出会打印来源 —— **静默套用配置比不套用更危险**，你会以为甲乙方是自己当场指定的。

## 支持与不支持

| | 支持 | 说明 |
|---|---|---|
| `.txt` / `.md` | ✅ | 自动尝试 utf-8-sig / utf-8 / gb18030 / gbk / big5 |
| `.docx` | ✅ | 正文段落 + 表格文本 |
| `.pdf`（有文本层） | ✅ | 依赖 `pypdf` |
| `.pdf`（扫描件） | ❌ | 无文本层，`info --probe-text` 会明确列出 |
| `.doc`（旧版） | ❌ | 明确报错并给出转换方法，不静默跳过 |
| `.xlsx` / 图片等 | ❌ | 逐个列出原因，并各占一行台账（状态为「不支持格式」） |

隐藏文件、`.git` / `node_modules` / `__pycache__` 等噪声目录、`~$` Office 临时文件会被直接排除，不进入统计。

| | 不支持（能力边界） |
|---|---|
| **条款风险审查** | 判断「这条对我方是否不利」需要立场和法律判断，不是事实抽取。台账只要事实 |
| **效力与续签判断** | 出具这类意见有法律责任。本工具只报「到期日期是 X」 |
| **当事人名称 100% 准确** | 合同是自由文本，名称写法千变万化。实测会混入「XX仲裁委员会」这类机构名（置信度通常 0.55）。**低于阈值（默认 0.70，可用 `--conf-threshold` 调）一律进「待确认字段」** |
| **表格版式的合同** | 数字在表格里、没有「合同金额：」标签时可能抽不到（实测拿 0 个候选）。这类情况现在会**主动告警**并指向 `pdf-toolkit tables`，不用你自己猜为什么是空的 |
| **一份合同多个文件自动合并** | 正文 + 附件 + 补充协议会各自产出一行。合同缺少天然唯一标识，合并只能靠弱键，**宁可先不合并，也不要猜错** |
| **OCR** | 见下 |
| **联网** | 任何形式都不 |

### 扫描件 / 拍照件：请先用 OCR，再进本工具

两步走：

1. **把纸变成字** —— 用 `pdf-toolkit` 技能的 `text` 子命令，输入扫描件 PDF、输出 txt 并开启 OCR（该技能不在本包内，需另行安装；`--ocr` 依赖系统层的 tesseract + chi_sim）：
   `text <扫描合同.pdf> <扫描合同.txt> --ocr`
2. **把字变成台账** —— 用本工具处理转出来的文本：

```bash
python scripts/contract_toolkit.py parse 扫描合同.txt 台账.xlsx
```

不在本工具内置 OCR：会让「零重型依赖」破功（tesseract 需系统层安装），而且 OCR 准确率无法承诺，会污染台账的置信度体系。扫描件先用 `info --probe-text` 认出来，再走上面的路径。

## 环境

- Python ≥ 3.10
- 必需：`pandas>=2.0`、`openpyxl>=3.1`
- 可选：`pypdf>=5.0`（读 PDF）、`python-docx>=1.1`（读 DOCX）、`pytest>=8.0`（跑测试）

**不引入**：PyMuPDF（AGPL，与本技能 MIT 声明冲突）、easyofd、pytesseract、paddleocr、ollama。
