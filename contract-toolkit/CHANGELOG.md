## [1.0.2] - 2026-10-08

可用性补强。**没有新抽取能力** —— 改的都是「明明能做却做不到 / 文档说能做实际没做」这一类。

### 新增

- **`--conf-threshold`（`parse` / `check`）** —— 置信度阈值可调，默认 `0.70`，取值 `(0, 1]`。
  原先 `0.70` 硬编码在四个地方（`pending` 属性、xlsx 条件着色、`--probe` 的 `!!` 标记、
  结尾提醒文案），意味着**四处的口径只能靠人记住保持一致**；这四处现在统一读模块级
  `CONF_THRESHOLD`，由 `main()` 一处校验写入。不同批次的合同质量差异很大 ——
  写得规范的批次可以调高，写得散的批次调低，不至于整列都是「待确认」而失去信号。
- **HTML 报告** —— 输出路径写 `.html` 即得单文件自包含报告（内联 CSS、零外部资源、
  无 CDN），`parse` / `check` / `expire` / `compare` 全部支持。给不装 Excel / WPS 的
  接收方看：双击就能开，断网也能看，整份报告就是一个文件。超长表只预览前 300 行
  并注明 —— 几百份合同全量内联会让单文件膨胀到几十 MB，完整数据本来就在同名的 xlsx 里。
- **`--our-name` 的默认值来源** —— 除命令行外，支持环境变量 `CONTRACT_OUR_NAME` 与
  配置文件 `.contract-toolkit.yaml`（查输入目录及其上级 → 当前目录 → 用户主目录）。
  配置文件**刻意不引 PyYAML**（零重型依赖是本技能的卖点之一），只认 `键: 值` 单层写法
  与 `#` 注释，内容以 `{` 开头时按 JSON 读。命中默认值时会**显式打印来源** ——
  静默套用配置比不套用更危险，用户会以为台账里的甲乙方是自己当场指定的。
- **表格版式的定向提示** —— 金额 / 日期抽不到且文本确实带表格特征时，告警直接指向
  `pdf-toolkit` 的 `tables` 子命令。判据（≥3 行且占比 ≥30%）刻意保守：告警一旦开始
  误报，用户就不再逐条看，等于没有告警。有反向用例钉住「普通条款式合同一条表格告警都不该有」。
- **`examples/make_payment_samples.py`** —— 生成演示用银行流水，并给出「台账 → 核销」
  的完整可跑命令。样例刻意留了缺口（实付比合同金额少 20,000、另有一笔对不上任何合同），
  因为对账工具的价值在于把差异摆出来，一份全部匹配的样例证明不了任何事。

### 修复

- **文档引用了不存在的子命令**：`SKILL.md` 写着「可用 `link` 把合同付款节点与流水核销」，
  而 `reconcile-toolkit` 的子命令是 `rule` / `recon` / `summary` / `info` / `check`，
  **根本没有 `link`**。照着文档敲只会得到 `invalid choice: 'link'`。已改为 `recon`
  并补上完整的四步实操（含实测输出与三类结果的读法）。
  `check_examples` 检查不到这类问题 —— 它只校验本技能的脚本，跨技能引用是盲区。
- **`--recursive` 的 help 与实现相反**：`parse` 的 `--recursive` 根本没有 help 文字；
  `info` 的 help 写着「递归子目录（默认开启）」，而实现是 `store_false` 配
  `recursive=not args.no_recursive` —— **实际默认不递归**。用户按 help 理解不传参，
  子目录里的合同就此消失且没有任何提示，属于典型的静默漏收（与 v1.0.1 修的那族缺陷同源）。
  现改为 `BooleanOptionalAction`、默认递归、help 写清 `--no-recursive` 的用法，
  `info` 还会在摸底结果里打印本次的处理范围。
- **键选错时工具不会报错、只会安静地说「全都不匹配」**：在补核销示例时实测发现，
  拿台账的「合同标识」（文件名）去对流水里的「合同编号」，会得到 **0 个匹配**。
  这个坑已写进文档，并把示例改成用「合同编号」这一两侧都真实存在的列做键。

### 测试

- 141 → **167 passed**（新增 23 个用例 + 1 个参数化）。
- 新增 `autouse` fixture 隔离**本机环境与全局状态**：`CONTRACT_OUR_NAME` 环境变量、
  本机的 `.contract-toolkit.yaml`、以及被 `main()` 改动的模块级 `CONF_THRESHOLD`。
  不隔离的话，本机一旦配过我方名称，所有 parse 用例的甲乙方判定都会跟着变，
  测试就不再可复现 —— 而这恰恰是 v1.0.2 新增能力带来的**新**污染源。
- 断言按实测写而非按推测写：首次提交的两个阈值用例都被实际取值打回
  （探针里带了 `--our-name`、测试里没带，「对方名称」的置信度一个是 0.92、一个是 0.6；
  另外 `TXT_CLAUSE` 的字段比探针用的文本多，0.99 阈值下的待确认字段多出四个）。

### 验证

- 单测 167 passed；`check_meta` / `check_examples` / `check_tests` / `audit_icons` 全通过
- 五步全流程端到端实跑通过（含 `.html` 输出）
- 付款核销链路实测跑通：台账 → `recon --aggregate` → 差异报告
  （金额不符 1 / 仅右表有 1 / 左表键缺失 3）

## [1.0.1] - 2026-10-08

上架前的解包端到端复验挖出的问题。**没有新功能，只有一处真实缺陷 + 一批文档与实测不符。**

### 修复

- **目录模式下「其它扩展名」仍被静默跳过**（真实缺陷，v1.0.0 的承诺未兑现）。
  `collect_files` 当时只把「旧版 `.doc`」从扩展名过滤里放出来，`.jpg` / `.xlsx` 之流
  在过滤阶段依旧被丢掉。于是 SKILL.md 白纸黑字写着的
  「目录里混着 `附件清单.xlsx`、`照片.jpg` 这类文件时，`parse` 会给它们各写一行台账
  （状态为 `不支持格式`），保证「输入里有什么」和「台账里有几行」对得上」
  **是不成立的** —— 实测一个 5 文件目录只产出 3 行台账，`照片.jpg` 与 `附件清单.xlsx`
  无声消失，而 `info` 还把 `.doc` 同时算进「合计」和「需要先转换或不支持」两个维度。
  **同一类缺陷只修了一半**（.doc 修了，同类没修全），这是本次最值得记的一条。
  现改为统一口径：目录模式**只排除隐藏文件与噪声目录**（`.git` / `node_modules` /
  `__pycache__` / `~$` 临时文件 / `Thumbs.db` / 隐藏目录下的一切），其余一律收进来，
  不支持的格式各占一行台账（状态 `不支持格式`）并写进「解析告警」。
  新增 `NOISE_DIRS` / `NOISE_FILES` / `is_noise()` 作为那道闸门。
- **三条口径从此恒等**：`info` 的「合计」= `parse` 的「处理 N 个文件」= 台账行数。
  `info` 的「合计」改为目录内实际文件数，并在其后直接注明「N 个旧版 .doc 需先转换、
  M 个格式不支持，不会参与抽取」；原先的单列清单改题为「需人工处理 N 个（这些文件
  仍会进台账，状态列为「不支持格式」）」，并说明它与「合计」是**总量与子集**的关系，
  不要相加。
- **`parse` 空目录的错误文案**：`没有可处理文件（.pdf / .docx / .txt / .md）` →
  `没有找到任何文件（已排除隐藏文件与噪声目录）`（不再暗示按扩展名过滤）。

### 修复（文档与实测不符，均以「跑一遍」复核而非读代码推测）

- **`parse` 示例输出与它自己的命令不是同一次运行**：SKILL.md 里那条命令带

## [1.0.0] - 2026-10-07

首次发布。5 个子命令（`info` / `parse` / `check` / `expire` / `compare`），139 个单元测试。

### 新增

- **抽取内核**（`scripts/contract_toolkit.py`）
  - 中文大写金额解析：含零、含万/亿分级、含角分、连续零、缺「整」字、常见错别字
  - 阿拉伯金额归一：千分位、全角、货币符号与前后缀
  - 区域切分：头部（当事人与编号）/ 条款正文 / 尾部，用于收窄抽取窗口
  - 金额抽取与消歧：**先捞全部候选，再按锚点打分**。总价类锚点（合同总价 / 总价款 / 合同总金额）加高分，单价 / 税率 / 节点款 / 违约金比例分别降权；大小写金额同句交叉验证，一致则双向加分
  - 当事人抽取：组织名后缀词表（公司 / 企业 / 厂 / 中心 / 事务所 / 合伙企业 / 个体工商户…）+ 角色词（甲乙方、需供方、委托受托方、出租承租方…）**同行约束** + 分隔符优先
  - 日期抽取与归类：签订 / 生效 / 到期三字段，前置与后置锚点双向匹配，支持区间写法（「自 X 起至 Y 止」）
  - 付款节点抽取：节点名称 / 节点类型 / 比例 / 金额 / 约定时点，**窗口限定在同一分句内**
  - 置信度定级：低置信度字段汇总进「待确认字段」列
- **5 个子命令**
  - `info`：依赖自检 + 目录摸底；`--probe-text` 实际读一遍并识别无文本层的扫描件
  - `parse`：四 sheet 交付级 xlsx（合同台账 / 付款节点 / 抽取候选 / 解析告警）；`--probe` 单份详情、`--our-name` 指定我方全称、`--dry-run` 只统计、`-v` 逐份状态
  - `check`：8 条确定性规则，可用 `--rules` 只跑指定项、`--tolerance` 调金额容差、`--as-of` 定基准日
  - `expire`：按期分档（已到期 / 即将到期 / 未到期 / 无到期日期），`--only-expiring` / `--only-dated` 过滤
  - `compare`：分组汇总（合同数 / 金额合计 / 金额均值 / 已抽到金额条数 / 到期区间）+ 按 `--fields` 统计取值分布
- `examples/make_samples.py`：现场生成四份风格不同的样例（规范条款式 / 口语化正文式 / 表格版式 / 框架协议），覆盖四种典型形态与边界
- 四 sheet 台账样式与 `invoice-toolkit` 对齐：表头绿底白字、首行冻结、列宽自适上限 42、问题行条件着色

### 修复（开发过程中由实测挖出，均非肉眼可见）

- **生效日期成片抽不到**。三类写法都失败：「自 2026-10-01 **起至** 2027-09-30 止」（区间起点被错标成到期日）、「于 2026-10-01 **起正式**生效」（「起」与「生效」之间夹了修饰词）、「自双方签署之日**（**2026-10-01**）起生效**」（日期在括号内）。改为后置锚点优先 + 区间起点纠正 + 同句兼报。
- **修完上面三条后新引入一个回归**：`DATE_RE` 末尾的 `\s*日?` 把**换行也吃掉**，导致日期的「后缀窗口」越到下一行，「生效日期：X\n到期日期：Y」里第一个日期被下一行的标签抢走。改为 `[ \t]*日?`。
- **日期前置锚点跨行误抓**：「签订日期：2026-12-01\n本合同自 2026-10-01 起生效」里，第二行的日期被上一行残留的「签订日期」抢走。前置锚点改为限定在同一行内查找。
- **同行的两个标签会串字段**（「签订日期：X 生效日期：Y」同行排列时），补同句兼报与顺序判定。
- **当事人角色词跨行误关联**：「采购方」被错配给下一行的乙方公司名、「甲方」被配给仲裁委员会。角色词改为**必须与名称在同一行内**。
- **「合同总价的 5%」把比例带进总价候选**：锚点前是「合同总价」，实际是违约金比例。按锚点类型分级降权，实测该候选得分 −1.22 被正确落选。
- **违约金后置锚点抓不到**：「按合同总价的 0.5%…支付违约金」锚点在后。改为双向匹配。
- **付款节点比例跨句误抓**：「余款于验收通过后十日内付清。……任何一方违约支付 20% 违约金」中，后一条款的 20% 被当成余款的付款比例，导致比例合计 60%。节点窗口改为限定在同一分句内。
- **质保金被当成支付节点**：质保金是从尾款中扣留的，不是独立支付节点，计入会导致「比例合计 105%」这类误报。新增「节点类型」列区分 `支付节点` / `扣留项`，扣留项不参与 100% 合计。
- **「固定金额」里的「定金」被误当节点**：金额表述中的「定金」「订金」与付款节点锚点冲突。加词边界约束。
- **「大写一致」规则误报**：该规则原先把落选的单价（12000）、节点款（180000/420000）也算进「大写与数字金额不一致」。改判据为**只比中文大写金额与台账采纳金额**。
- **同句金额比较范围过宽**：被采纳的 600000 被标上「同句存在不同金额，需人工确认」，因为它把隔壁条款的 180000 算成了同句。分句边界收紧。
- **目录模式下旧版 `.doc` 被静默跳过**：`collect_files` 目录模式只收 `SUPPORTED_EXT`，`.doc` 在过滤阶段就被丢掉，用户会拿到一份「处理 5 个文件：正常 5」却少了那份 `.doc` 的台账。单文件模式当时会明确报错，**两条路径行为不一致，所以只在传目录时暴露**。现改为目录模式也收 `.doc`，以「异常/未提取」状态进台账并写进告警；`info` 也按「需先转换」与「不支持」两类分别提示，`.doc` 给出「另存为 .docx」的具体做法。
- **xlsx 写入崩溃**：write-only 模式下同一行混用 `WriteOnlyCell` 与普通值，lxml 序列化器错乱。
- **金额列被读成 object**：空值原写成空字符串，导致 pandas 读回时整列 dtype 变 `object`，无法直接求和。改为写真空单元格。

### 已知局限（明确写在文档里，不作为缺陷隐瞒）

- **当事人名称准确率有上限**：合同是自由文本。实测无角色词时会混入「XX仲裁委员会」这类机构名（置信度约 0.55）。低于 0.70 一律进「待确认字段」。
- **表格版式合同金额可能抽不到**：数字在表格里、后面没有「元」字、也没有「合同金额：」标签时，实测拿到 0 个候选。建议先用 `pdf-toolkit tables` 抽表格。
- **一份合同多个文件不自动合并**：正文 + 附件 + 补充协议各自产出一行。合同缺少天然唯一标识，合并只能靠「对方名称 + 金额 + 签订日期」这类弱键，**宁可先不合并，也不要猜错**。
- **不做 OCR**：扫描件请先用 `pdf-toolkit` 的 `text --ocr` 转文本。不内置的理由是依赖体积与准确率无法承诺。
- **不做条款风险审查、不做效力与续签判断**：前者需要立场与法律判断，后者有法律责任。
